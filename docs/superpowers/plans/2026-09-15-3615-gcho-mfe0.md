# 3615 GCHO MFE-0 Implementation Plan

> **For agentic workers:** implement task-by-task with tests and verification before completion.

**Goal:** Deliver a small GPE Web/WASM Minitel-style service at the repository GitHub Pages URL with external periodically generated editorial content.

**Architecture:** A game-local Rust state machine owns page navigation. A thin GPE adapter translates physical Enter/Escape and public `TextInputEvent` edits into Minitel commands. Rendering uses only GPE framebuffer primitives/text. JSON content is embedded at build time from repository snapshots and generated atomically before scheduled Pages builds.

**Tech Stack:** Rust 1.97.1, GPE pinned to `40e0af0`, serde/serde_json, Python 3 generator, wasm-bindgen 0.2.127, GitHub Actions/Pages.

**Spec:** `docs/3615_GCHO_MFE0_SPEC.md`

## Global constraints

- No GPE engine change unless a genuine missing capability is proven.
- No backend, database, CMS or runtime third-party API.
- Pages must work under `/gpe_3615_gcho/`.
- Content refresh failure must retain a valid committed snapshot.
- Keep architecture game-local and inspectable.

### Task 1 — Navigation state machine

Create the seven required page identities and test digit + ENVOI, CORRECTION, RETOUR and SOMMAIRE behavior before implementation.

### Task 2 — External content snapshots

Create four small JSON content files plus a typed loader with deterministic fallbacks. Add tests for valid parse and invalid-data fallback.

### Task 3 — GPE runtime and Videotex renderer

Add the short boot sequence, GPE input adapter, terminal renderer, native entry point and Web/WASM entry point. Keep framebuffer-only UI and ASCII-safe in-world copy.

### Task 4 — Deterministic content generator

Add `tools/generate_content.py` with atomic replace and `--check`. Regenerate only `service_public.json` from local approved templates using a UTC date seed.

### Task 5 — CI and GitHub Pages

Expand CI to fmt/test/clippy/Web checks. Add Pages workflow that refreshes content opportunistically, validates the resulting snapshot, builds WASM, packages a static `dist/`, and deploys from `main` or the daily schedule.

### Task 6 — Documentation and verification

Document local run, Web build, content regeneration, Pages behavior and MFE limitations. Use CI/Actions as the verification authority for this remote-only execution.
